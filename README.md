# Companies Service

A Go microservice that manages companies over a REST API. Every mutation publishes an event to Kafka.

- **Operations:** create, get, patch, and delete.
- **Auth:** create, patch, and delete require a JWT bearer token. Get is public.
- **Events:** `company.created`, `company.updated`, and `company.deleted` go to the `companies.events` topic. Delivery uses the transactional outbox pattern.
- **Concurrency:** writes use optimistic locking through `ETag` / `If-Match`.
- **Stack:** Go 1.26, chi, PostgreSQL 17 (pgx, goose), Kafka 4 (franz-go), zap, and Prometheus.

## Quick start

You need Docker with Compose v2. You need Go 1.26 only to run tests or the binary on the host; without Go, `make token` builds the token issuer in Docker.

```bash
make up        # build the image and start Postgres, Kafka, migrations, and the app
make token     # print a dev JWT for the local config
```

The API listens on `http://localhost:8080`.

```bash
TOKEN=$(make -s token)

# Create
curl -si -X POST localhost:8080/api/v1/companies \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"Acme","description":"Rockets","amount_of_employees":42,"registered":true,"type":"Corporations"}'
# HTTP/1.1 201 Created
# Etag: "1"
# Location: /api/v1/companies/0199...

ID=<id from the response>

# Get (public)
curl -s localhost:8080/api/v1/companies/$ID

# Patch: send the ETag you got. Fields you leave out stay unchanged. "description": null removes the description.
curl -si -X PATCH localhost:8080/api/v1/companies/$ID \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/merge-patch+json' \
  -H 'If-Match: "1"' -d '{"amount_of_employees":50,"description":null}'

# Delete
curl -si -X DELETE localhost:8080/api/v1/companies/$ID \
  -H "Authorization: Bearer $TOKEN" -H 'If-Match: "2"'

make events    # print the published events
make down      # stop the stack and remove its volumes
```

To run the binary on the host instead, start the infrastructure first:

```bash
make infra     # Postgres on :5432, Kafka on :9094
make run       # uses configs/config.local.yaml and applies migrations on start
```

## API

The full contract is in [`api/openapi.yaml`](api/openapi.yaml).

| Method | Path | Auth | Success | Errors |
|---|---|---|---|---|
| `POST` | `/api/v1/companies` | yes | 201 + `ETag`, `Location` | 400, 401, 409, 413, 415 |
| `GET` | `/api/v1/companies/{id}` | no | 200 + `ETag` | 400, 404 |
| `PATCH` | `/api/v1/companies/{id}` | yes | 200 + `ETag` | 400, 401, 404, 409, 412, 413, 415, 428 |
| `DELETE` | `/api/v1/companies/{id}` | yes | 204 | 401, 404, 412, 428 |

Company fields:

| Field | Type | Rules |
|---|---|---|
| `id` | uuid | Always present. Generated by the server (UUIDv7), so clients cannot choose or collide IDs. Read-only. |
| `name` | string | Required. 1 to 15 characters, counted as Unicode characters. Leading and trailing spaces are removed. No control characters. Unique, case-insensitive. |
| `description` | string or null | Optional. Up to 3000 characters. Control characters are rejected, except tab and line breaks. |
| `amount_of_employees` | int | Required. From 0 to 2147483647. |
| `registered` | bool | Required. |
| `type` | enum | Required. One of `Corporations`, `NonProfit`, `Cooperative`, `Sole Proprietorship`. |
| `version`, `created_at`, `updated_at` | | Read-only. |

Request bodies must be a single JSON object of at most 64 KiB. `POST` needs `Content-Type: application/json`. `PATCH` needs `application/merge-patch+json` or `application/json`. Field names are case-sensitive. Unknown fields, read-only fields, and fields with a wrong JSON type are reported per field, in the same format as validation errors. A body of `null` is rejected.

Errors use [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) `application/problem+json`. Validation errors list every field that failed:

```json
{"type":"about:blank","title":"Bad Request","status":400,"detail":"validation failed",
 "instance":"/api/v1/companies","request_id":"host/abc-000001",
 "errors":[{"field":"name","message":"must be at most 15 characters"}]}
```

### Optimistic locking

Every company has a `version`. Responses return it as a strong `ETag`, for example `"3"`. `PATCH` and `DELETE` require an `If-Match` header with that ETag:

- If `If-Match` is missing, the response is `428 Precondition Required`.
- If the company changed since the client read it, the response is `412 Precondition Failed`. Get the company again, then retry.

The database enforces the check with `UPDATE ... WHERE id = $1 AND version = $2`. When several clients write with the same version at the same time, exactly one succeeds.

### Authentication

The service only validates tokens. An external identity provider issues them. The checks are:

- The signature must use `HS256` (shared secret) or `RS256` (PEM public key from `jwt.public_key_file`).
- `exp` is required.
- `sub` is required.
- `iss` and `aud` are checked when they are set in the config.

`tools/devtoken` signs tokens for local use only.

## Events

The service writes each mutation and its event to the `outbox` table in the same transaction. A background relay reads outbox rows with `FOR UPDATE SKIP LOCKED`, sends them to Kafka (`acks=all`, idempotent producer), and then deletes them.

- **Delivery:** at-least-once. An event is never lost when Kafka is down, and an event is never sent for a rolled-back write.
- **Scaling:** several replicas can run the relay at the same time.

The payload is stored as `json`, not `jsonb`, so Kafka gets exactly the bytes the service serialized.

Each record has:

- **Key:** the company id. All events of one company go to the same partition.
- **Headers:** `event_id` and `event_type`.
- **Value:**

```json
{
  "event_id": "0199...",
  "event_type": "company.updated",
  "occurred_at": "2026-10-17T10:00:00.123456Z",
  "company": {"id":"0199...","name":"Acme","description":null,"amount_of_employees":50,
              "registered":true,"type":"Corporations","version":2,
              "created_at":"...","updated_at":"..."}
}
```

`company.deleted` carries the last state of the company, with `version` incremented once more. So every event of a company has a strictly greater `version` than the one before, and a consumer can drop any event whose `version` is not greater than the last one it applied.

Consumers must deduplicate by `event_id`. With several replicas, order across batches is not strictly guaranteed, so use `company.version` as described above.

## Configuration

The service reads one YAML file. Set its path with `--config` or `CONFIG_PATH`. The default is `configs/config.yaml`. `${VAR}` references in values are replaced with environment variable values, so secrets stay out of the file.

| File | Purpose |
|---|---|
| [`configs/config.yaml`](configs/config.yaml) | Production template. Baked into the image. All environment-specific values come from env variables. |
| [`configs/config.local.yaml`](configs/config.local.yaml) | Running on the host against `make infra`. |
| [`.env.example`](.env.example) | Env values that Docker Compose uses. |

Environment variables used by `configs/config.yaml`:

| Variable | Purpose |
|---|---|
| `LOG_LEVEL` | `debug`, `info`, `warn`, or `error`. Default `info`. |
| `POSTGRES_DSN` | Postgres connection string. Required. |
| `KAFKA_BROKERS` | Comma-separated broker list. Required. |
| `KAFKA_TLS_ENABLED`, `KAFKA_TLS_CA_FILE`, `KAFKA_TLS_CERT_FILE`, `KAFKA_TLS_KEY_FILE` | TLS to Kafka. Cert and key enable mTLS. |
| `KAFKA_SASL_MECHANISM`, `KAFKA_SASL_USERNAME`, `KAFKA_SASL_PASSWORD` | SASL: `PLAIN`, `SCRAM-SHA-256`, or `SCRAM-SHA-512`. Empty disables SASL. `PLAIN` requires TLS, otherwise the service refuses to start. |
| `JWT_ALGORITHM`, `JWT_SECRET`, `JWT_PUBLIC_KEY_FILE`, `JWT_ISSUER`, `JWT_AUDIENCE` | Token validation. |

Variables are substituted after the YAML is parsed, so values may contain any characters, including `#`, `&`, `*`, `{`, quotes, and line breaks. A variable that is unset or empty keeps the built-in default.

## Operations

- **Commands:**
  - `companies serve` runs the API and the outbox relay.
  - `companies migrate` applies migrations and exits. Run it as a release job or init container. Alternatively, set `postgres.migrate_on_start: true`.
- **Probes:**
  - `GET /health` is the liveness probe.
  - `GET /ready` is the readiness probe. It checks Postgres only and reports `ok` or `fail` per check; the error itself goes to the log. Kafka is left out on purpose: while Kafka is down, writes still succeed and events wait in the outbox, so pulling every pod out of the load balancer would only make things worse. Alert on `companies_outbox_oldest_age_seconds` instead.
- **Metrics:** `GET /metrics` on the admin port (`http.admin_addr`, default `:9090`), not on the public API port. It exposes:
  - HTTP request counts and latency per route;
  - `companies_outbox_published_total` and `companies_outbox_failures_total`;
  - `companies_outbox_pending` and `companies_outbox_oldest_age_seconds`, refreshed every `outbox.backlog_interval`. Alert on the age: it grows when Kafka is unreachable;
  - Go runtime and process metrics.
- **Logs:** JSON from zap. One access log line per request, with `request_id` and the JWT subject.
- **Shutdown:** on `SIGTERM`, the service stops accepting requests, finishes in-flight requests, and stops the relay. The time limit is `http.shutdown_timeout`.
- **Image:** multi-stage build on `distroless/static:nonroot`. The binary is static.

## Development

```bash
make test               # unit tests with -race
make test-integration   # end-to-end tests with testcontainers (Postgres and Kafka). Needs Docker.
make lint               # golangci-lint (version pinned in .golangci-version)
make docker-build       # build the production image
make help               # list all targets
```

The integration tests in `test/integration` start the whole application against real containers. They cover:

- the full create, get, patch, and delete flow, with a check that all three events reach Kafka in order;
- case-insensitive name uniqueness;
- concurrent patches with the same ETag, where exactly one wins;
- validation and authentication errors.

GitHub Actions (`.github/workflows/ci.yml`) runs lint, unit tests, and integration tests, and builds the image.

## Layout

```
cmd/companies/                 entry point (serve, migrate)
internal/domain/               entities, validation rules, domain errors, events
internal/usecase/company/      business operations; transaction and outbox orchestration
internal/usecase/outbox/       relay from the outbox to the broker
internal/adapter/storage/postgres/  repositories, transaction manager, migrations runner
internal/adapter/kafka/        Kafka publisher
internal/adapter/jwt/          token validator
internal/transport/http/       chi router, handlers, DTOs, middleware
internal/app/                  dependency wiring and lifecycle
internal/config/               YAML config loading
internal/observability/        zap logger, Prometheus metrics
migrations/                    goose SQL migrations (embedded into the binary)
test/integration/              end-to-end tests
tools/devtoken/                dev-only JWT issuer
```

Dependencies point inward. Transport and adapters depend on use cases and the domain. Use cases depend only on interfaces they define themselves.
